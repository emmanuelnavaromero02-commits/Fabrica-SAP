# Fiori Elements — templates and FPM extensions

Hard rule: for CRUD use cases, Fiori Elements only. UI5 controllers for CRUD are banned.

## Template selection (from G4)

| Use case | Template |
|---|---|
| List of records + detail + edit | **List Report + Object Page (LROP)** — default |
| Work queue with filters | Worklist |
| KPI tiles / cards | Overview Page (OVP) |
| Analytics with filter bar + chart | Analytical List Page (ALP) |
| Single form input | FPM Form |

## LROP minimum annotations

These must exist in the projection's `.ddlx` or the LROP renders blank:

1. `@UI.headerInfo` on the entity.
2. At least one field with `@UI.lineItem`.
3. At least one field with `@UI.identification`.
4. At least one field with `@UI.selectionField`.
5. Currency/quantity semantics on all numeric business fields.

Without all five, FE generates a UI that "works" but looks broken to the user. The factory rejects this — `check_handoff.py` flags missing annotations.

        "type": "OData",
        "settings": { "odataVersion": "4.0" }
      }
    }
  },
  "sap.ui5": {
    "models": {
      "": {
        "dataSource": "mainService",

## OData V4 model settings — non-negotiable defaults

- `autoExpandSelect: true` — FE picks the right `$select` and `$expand` from annotations.
- `earlyRequests: true` — faster perceived load.
- `operationMode: "Server"` — pagination, sorting, filtering on the server.
- `synchronizationMode: "None"` — V4 doesn't use sync mode the way V2 did.

## OVP — Overview Page

Cards are defined in `manifest.json` under `sap.ovp`:
```json
"sap.ovp": {
  "globalFilterModel": "",
  "globalFilterEntityType": "<EntityType>",
  "cards": {
    "card01": {
      "model": "",
      "template": "sap.ovp.cards.list",
      "settings": {
        "title": "Top <Entities>",
        "entitySet": "<Entity>",
        "selectionVariant": "<qualifier>",
        "presentationAnnotationPath": "@UI.PresentationVariant"
      }
    }
  }
}
```

Cards reference annotations in the CDS — `@UI.PresentationVariant`, `@UI.SelectionVariant`, `@UI.DataPoint`, `@UI.Chart`.

## ALP — Analytical List Page

Requires:
- CDS with `@Analytics.dataCategory` (`#CUBE`, `#DIMENSION`, `#FACT`).
- `@UI.Chart` annotation.
- `@UI.PresentationVariant` referencing chart and table.
- `@UI.SelectionPresentationVariant`.
- Provider contract `analytical_query` on the projection.

## Flexible Programming Model — custom extensions

When Fiori Elements is 95% right and you need 5% custom:

```json
"<Entity>Detail": {
  "name": "sap.fe.templates.ObjectPage",
  "options": {
    "settings": {
      "contextPath": "/<Entity>",
      "content": {
        "body": {
          "sections": {
            "CustomSection": {
              "template": "zdswf.<entity>.ext.CustomSection",
              "title": "{i18n>customSection.title}",
              "position": { "placement": "After", "anchor": "GeneralInfo" }
            }
          }
        }
      }
    }
  }
}
```

Custom section JS at `webapp/ext/CustomSection.js`:
```js
sap.ui.define([
  "sap/fe/core/PageController"
], function (PageController) {
  "use strict";
  return PageController.extend("zdswf.<entity>.ext.CustomSection", {
    // event handlers, but no business logic
  });
});
```

Hard limit: custom controller code must not contain business logic. Business logic stays in RAP.

## Controller extensions

For action confirmations, validations on UI side (for UX only — server-side validation is still mandatory):

```js
"extends": {
  "extensions": {
    "sap.ui.controllerExtensions": {
      "sap.fe.templates.ObjectPage.ObjectPageController": {
        "controllerName": "zdswf.<entity>.ext.ObjectPageExt"
      }
    }
  }
}
```

## i18n

`webapp/i18n/i18n.properties` (English by default) plus `i18n_es.properties`, `i18n_pt.properties` as needed. No literal strings in XML or JS. ZDSWF policy: minimum English + Spanish + Portuguese for LatAm work.

## Common errors

| Symptom | Cause | Fix |
|---|---|---|
| Blank list page | Missing `@UI.lineItem` annotations | Add annotations in .ddlx |
| "No data" but data exists | DCL blocks user | Check DCL and user authorization |
| Filter doesn't reload | `initialLoad: false` and no user trigger | Set `initialLoad: true` |
| Edit button missing | BDEF missing `update;` or projection missing `use update;` | Add to BDEF and projection BDEF |
| Save fails with `412` | ETag stale | Refresh, check `total etag` config |
| Action button greyed out | `get_instance_features` returns disabled | Implement features to return enabled when applicable |
